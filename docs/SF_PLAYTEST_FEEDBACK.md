# VOID CARAVAN — 직접 플레이 피드백 및 검증 대기

이 문서는 **사용자가 실제로 플레이하고 보고한 느낌**을 우선 기록한다. 개발자 자체 평가, 자동 테스트, 이슈 가설과 혼동하지 않는다. 최신 SF 제품 방향은 [SF_PIVOT_PLAN.md](SF_PIVOT_PLAN.md)를 따른다.

## 2026-11-25 · SF 0.1 사용자 피드백

> "타격감이 없어 그리고 탐험하는 재미도 없고 아직 기본 단계구현이라 그렇지?"

**근거:** 사용자가 웹에서 플레이한 뒤 보고한 직접적인 주관적 피드백. 정확한 기기/동영상/정량값은 미확인. 이 피드백이 중요한 이유는 SF 0.1이 몬스터 사냥의 기본 조작을 보여줄 뿐 완결된 원정 게임이 아니기 때문이다.

### P0 — 공격이 맞는 쾌감/반격의 손맛 부족 (실제 플레이 사용자 불만)

- **문제:** 사용자는 현재 전투의 타격감이 없다고 평가. 코드에서 공격 명중·HP 변화가 있는 것과 사용자에게 타격이 전달되는 것은 다르다.
- **다음 1순위 개발 실험:** 먼저 단일 적 1종과 기본 공격 1개에 한정해 공격 준비→명중→적의 방향성 있는 경직/넉백→짧은 hit-stop→적합한 충돌 섬광·파편→소리/진동 가능 시 보완을 유기적으로 연결한다. 기존 입력 반응 속도를 손상시키지 않아야 하며 화면 흔들림은 작고 옵션으로 끄거나 줄일 수 있어야 한다. 과도한 화면 흔들림, 번쩍임, 텍스트 안내만 추가 금지. 바로 다양한 무기/스킬을 늘리지 않는다.
- **최소 수용 테스트:** 동일 몬스터를 같은 조건으로 전/후 비교한 화면 녹화와 제어 테스트(명중은 1회만, 회피/가드 시 명중 연출 없음, 입력 지연/카메라 클리핑 회귀 없음). 실제 사용자에게 **'한 번 공격할 때 제대로 맞는 느낌이 전보다 나는가?'** 확인. 자동 테스트만으로 주관적 타격감 '해결' 판정 금지.
- **현재 상태:** OPEN / 실측 미검증 / 엔진·코드 개선 및 사용자 재평가 필요.

### P0 — 이동/전투는 있어도 행성을 탐험할 동기가 없음 (실제 플레이 사용자 불만)

- **문제:** 현재 SF 0.1에는 세계를 알아가는 발견/방향 선택/위험-보상/숨은 보상/귀환 연결이 없어, 몬스터가 있는 평면 전투장으로 느껴질 수 있다. '행성 탐험'이라는 핵심 약속이 아직 미구현.
- **전투 타격감 실험 다음 개발 순서:** 60~120초 짧은 원정 하나에 2갈래 길(위험한 곳은 높은 가치의 부품/동료 흔적), 시각적으로 차별화된 지형 표식, 플레이어가 직접 찾는 구조된 외계 생물 1종의 발견, 전리품 회수/귀환 지점을 붙인다. 수집·제작·우주선으로의 인과 관계는 다음 수직 슬라이스에서 반드시 연결. 지도 UI/긴 튜토리얼·넓지만 빈 오픈월드 금지.
- **최소 수용 테스트:** 설명 없이 신규 플레이어가 '다음에 어디를 탐색할지' 선택하고, 위험 루트를 택한 이유 또는 의외의 발견 한 가지를 이야기하며, 얻은 부품/동료가 우주선으로 돌아갈 가치를 제공하는지 관찰. 시드/경로별 보상 차이는 자동 검증, '탐험이 재밌다'는 직접 사용자 확인.
- **현재 상태:** OPEN / 신규 핵심 시스템 미구현 / 직접 사용자 재평가 필요.

## 개발 세션 반영 규칙

1. 기존 시간별 개발의 우선순위는 **P0 타격감 먼저**, 그 다음 **P0 실제 탐험 발견**, 이후 외계 생물 동료/우주선 제작 판매/확장/덱빌딩. 이로 인해 게임 플레이가 없는 단순 메뉴/수치 기능을 늘리지 않는다.
2. 자동화 매 실행은 최신 GitHub main과 이 문서의 상태를 확인하고, 한 번에 한 가지 가설을 구현→테스트→브랜치/PR→CI 검증→main/Pages 배포 확인한다.
3. 직접 플레이 없이 '타격감 해결', '탐험 재미 완성'이라고 쓰지 않는다. 사용자 피드백을 듣기 전까지는 개선 '실험'이다.
4. 원본 과일 게임은 `legacy/harvest-deck-v0.8.11` 브랜치에 보존한다.
