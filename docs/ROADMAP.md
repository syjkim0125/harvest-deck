# Roadmap

최신 사용자 승인: Godot으로 저장소 없이 먼저 개발하고 매시간 이어간다.
오류는 원인 분석·수정·재검증한다. 막힌 작업은 독립적으로 가능한 작업과 구분한다.
웹 Sites 프로토타입에 이 프로젝트를 덮어쓰거나 되돌리지 않는다.

## 다음 실행의 우선 작업

1. 최신 ZIP/이 문서/코드를 읽고 테스트를 실행한다.
2. 렌더 가능한 환경을 확보할 수 있으면 실제 창으로 조작·겹침·UI·화면 흔들림 확인.
3. 원본 영상 8~24초의 캐릭터 크기 대비 이동·절삭 주기를 계측하고 실험값과 비교.
4. G1의 검증 공백이 남으면 솔직히 기록하되 독립적인 G2 가공/재고 상태 분리 구현을 진행할 수 있다. G1을 DONE으로 바꾸지 않는다.
5. 저장 전 테스트, HANDOFF 갱신, 동일 ZIP 버전 가드 교체. 영상·환경 장애만 반복 보고하지 않는다.

## v0.2 다음 항목
G1을 DONE으로 바꾸지 않는다. 실제 렌더 환경을 확인하고 연속 절삭 루프 음향과 원본 8~24초의 프레임 단위 추적을 우선한다. 독립 구현이 필요하면 장식 손님을 실제 대기열/응대 상태로 바꾸고 완제품 소비와 연결한다. 새 카드/낮밤은 아직 추가하지 않는다.

## v0.3 다음 항목
G1 반동과 판정을 분리했고 Linux 화면·조작 확인을 시작함. 다음 우선순위는 G1 연속 절삭 루프 음향(명중 순간의 부하음)과 원본 프레임 계측. G2 다음은 계산원 고용으로 직접 응대를 자동화하는 기능. PLAY_CHECK.md에 수동 조작 근거가 있음.

## v0.4 다음 항목
G1 새 루프는 구현/자동검증 및 실제 창에서 상태전환 확인. 인간 청음·장치 수명·원본 타격 템포
비교가 남음. 원본 랜드마크200ms 구간 측정 시작. 후속 여러 구간의30fps 추적 필요.
다음 독립 구현은 G2 계산원 고용/직접응대 자동화. 이후 시설 확장/과일 해금.

## v0.5 다음 항목
계산원 고용과 과일 구역에서의 자동판매를 실제 창에서 확인함. 다음 G2 범위는
시설 확장(추가 믹서/작업속도 등 최소 하나), 가격·구매 중복·재고 보존 검사.
G1 원본30fps 다구간 계측/청음/인간손맛 검증은 여전히 남음. G1/G2 완료 선언 금지.

## v0.6 다음
단일 믹서 속도 강화를 실제 구매/가공에 연결하고 UI 조작 확인. 다음 G2는 과일 해금과
해금 전 수확/재생성/납품 제한의 일관성. 기존 두 종류가 처음부터 열려 있으므로
진행 설계 변경 시 기본형 비교 체크포인트를 보존하고 영향받는 리플레이를 명시.
G1 원본 모션/청음/인간손맛 비교는 여전히 필요. G1/G2 완료 선언 금지.
