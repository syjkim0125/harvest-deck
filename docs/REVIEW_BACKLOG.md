# Harvest Deck — 독립 게임디자인 QA / 리뷰 백로그

최종 갱신: 2026-11-24 (KST). 기준 게임: 휴대폰 세로 한 손 터치용 Godot 4.6.3. 개발은 별도 매시간 실행, 이 문서는 **독립 리뷰→개발 세션 전달**의 단일 출처다.

## 비전 (변경 금지, 사용자 승인 없이 장르 변경 금지)

- **낮:** Vampire Survivors식 추적 적/자동 공격/전투 중 카드 성장 + Chainsaw Juice King의 생동감 있는 수확·타격·재료 축적.
- **밤:** 손님·주문·재료·가공대·진열대·판매/대기열이 보이는 상점 타이쿤. Overcooked 같은 시간·동선 선택의 재미를 가볍게 섞되 과도한 조작 압박은 피한다.
- **덱:** 낮과 밤에 서로 다른 결정/카드 사용법이 있고, 재료→매출→업그레이드/덱→다음 낮으로 이어지는 하나의 경제·성장 루프. 단순한 메뉴 선택 버튼이나 일회성 버프 카드 모음은 덱빌딩의 성공으로 인정하지 않는다.
- **시각 UX:** Cut the Rope/Where's My Water?처럼 사물 자체가 어포던스다. 7세 아동도 긴 텍스트나 메뉴 없이 첫 조작을 짐작하도록 목표를 세우되, *실제 아동 테스트 전에는 입증되었다고 쓰지 않는다*. PC 키보드는 필수 조작 경로가 아니다.
- **감성:** 독창적이고 일관된 미술 방향(실루엣/팔레트/아이콘/애니메이션/음향/설비의 물리적 관계). 대충 섞은 AI 생성 그래픽, 텍스트 덕지덕지, 버튼형 모의 대시보드를 개선 우선순위 최상단에 둔다. 기존 게임의 원본 자산은 복제하지 않는다.

|---|---:|---|

**별도 차단 조건:** 필수 PC 키보드 조작, 버튼/텍스트가 플레이 공간 대부분을 점유, 낮/밤 중 하나가 사실상 정적 메뉴, 두 덱의 상호 영향 부재, 심각한 모바일 터치/가시성 문제, 수확 타격감의 뚜렷한 퇴보. 구현이 완료됐더라도 '사용자 비전 미달(P0)'로 표기한다. 개발 편의보다 원래 의도에 우선권을 둔다.

## 피드백 작성 규칙

1. 매 실행 최신 **main의 커밋 SHA와 버전** / 최신 `docs/MOBILE_MVP.md`, `docs/ROADMAP.md`, `docs/HANDOFF.md` / 게임 실행 가능 링크 `https://syjkim0125.github.io/harvest-deck/`를 확인. 마지막으로 평가한 커밋과 비교해 새 변경에만 새 피드백을 기록한다. 비교판 `?lab=1`와 기존 v0.7.20 수확 반응을 회귀 기준으로 둔다.
2. 가능하면 실제 웹/휴대폰 세로 게임을 열어 **보이는 화면, 드래그, 레벨업 카드, 밤 설비 드래그/탭, 판매 및 다음 낮**까지 확인한다. 불가능하면 코드·스크린샷·테스트 근거 기반 *정적/간접 리뷰*라고 분명히 적는다. 실기기, 아동, 청음, 프레임 지표를 수행하지 않았다면 절대 검증 완료라고 쓰지 않는다.
3. 리뷰에서 이론의 이름만 인용하지 말고 **관찰된 문제→왜 재미/이해를 해치는지→한 가지 작은 수정→통과할 플레이 테스트**를 연결한다. 사용자가 싫다고 한 메뉴·텍스트·키보드 위주의 해결책을 다시 내지 않는다.
4. 카드를 더 만드는 대신 **두 후보 선택의 결과를 동등한 조건에서 비교**, 플레이어가 의미 있는 갈등을 경험하는지 먼저 확인한다. 상점에서 카드가 세계 속 물체를 움직이는지 확인한다.
5. 각 보고서에는 `평가한 커밋/버전 · 이전 대비 변경 · 7개 영역 평가(확인 가능할 때만) · P0/P1/P2 최대 3건 · 재현 근거 · 사용자 플레이 체감 · 우선 수정안 · 수용 조건 · 미검증 사항`을 기록한다. 이 문서 아래 기록에 누적하여 중복 이슈는 반복 등록하지 않는다.
6. 개발 세션에 넘길 **P0/P1 우선순위**를 상단에 유지한다. 개발 세션이 승인된 범위 안에서 한 항목씩 반영하도록 요청한다. 리뷰 자동화는 게임 코드를 직접 구현하지 않는다. 기술 구현 경로는 개발 작업의 판단에 맡기되 게임의 핵심 방향이 어긋나면 경고한다.

## 현재 리뷰 기준선 및 전달할 다음 과제

- 최신 설계 보고 기준 v0.8.0은 36초 낮 수확/전투 + 밤 손패·설비·손님·가공 + 첫날 덱 보상의 다음 날 이월을 구현했다고 기록한다. **문서상 구현 주장**이며 독립 실기기 리뷰 결과가 아니다.
- **P0 — 사용성 검증:** 첫 90초, 설명·키보드 없이 드래그 → 레벨업 카드 → 밤 카드→믹서→판매를 처음 보는 사람이 스스로 발견하는지 모바일 세로 환경에서 확인. 실패한 정확한 단계와 화면 근거로 개선한다.
- **P1 — 밤의 감각:** 카드가 재료와 설비를 실제로 움직이는지, 시간/손님 병목이 흥미로운 선택을 만드는지 확인. 버튼/장부만 보이면 화면을 재설계한다.
- **P1 — 덱 연결:** 같은 낮 결과에서 다른 밤 카드가 매출/손님 흐름을 바꾸는지, 다음 날 낮 선택이 실제 바뀌는지 AB로 검증한다.
- **리뷰 누적 전 상태:** 평가 점수 미산정. 실제 플레이/화면 근거를 검토하기 전 임의로 합격 판정을 내리지 않는다.

## 주기별 독립 리뷰 기록

새 리뷰는 `### YYYY-MM-DD HH:MM KST — 버전 / SHA` 형식으로 아래에 **추가**한다. 동일 SHA라도 새로 확인한 실기기·UX 증거가 생겼을 때만 별도 기록한다. 마지막 리뷰에서 열린 P0/P1의 처리 여부를 추적한다.
