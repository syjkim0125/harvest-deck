## 기본 원칙

- **게임플레이 개발 세션**은 `scripts/`, `scenes/`, `tests/`, `project.godot`, 웹 export/배포 및 실제 기능·안정성을 소유한다. 사용자의 플레이 피드백(P0 타격감·탐험)을 최우선.
- **디자인 작업 세션(별도로 도입 시)**은 **독창적 아트 디렉션, 콘셉트 탐색, UI 읽기, 캐릭터/외계 생물 실루엣, 배경/애니메이션·사운드 제작 규격**에만 집중한다. 개별 상용 게임의 스크린샷과 원본 자산은 게임에 넣지 않는다.
- 게임 엔진 내부 아트 변경은 **기존 개발 세션의 main 변경과 충돌할 수 있다.** 디자인 세션은 반드시 `design/*` 독립 브랜치와 `assets/concepts/` 또는 `assets/design-proposals/`처럼 격리된 경로를 사용한다. `main` 직접 병합/강제 푸시 금지. 교차 수정이 필요한 씬/스크립트는 **디자인 PR에 시각적 제안만 남기고 개발 세션이 별도 통합한다**.
- **최신 사용자 지정 스타일**은 [ART_DIRECTION.md](ART_DIRECTION.md)의 회화적 2D 무대/애니메이션 원리 × 유아 도식(Kindchenschema)에 기반한 귀여운 생물이다. 기존의 절대적인 픽셀 그리드·원본 캐릭터 비율 강제보다 우선한다(구체적 제작 방식은 실기기 시안 비교 후 선택).
- 디자인 작업은 **매번 전체 레퍼런스 18개를 펼치지 않는다.** [DESIGN_REFERENCE_ROUTER.md](DESIGN_REFERENCE_ROUTER.md)에서 해당 장면 1행과 1~2개(최대 3개) 원본 출처만 골라 읽는다. 게임 메커닉 구현은 [REFERENCE_ROUTER.md](REFERENCE_ROUTER.md)를 사용한다.
- 사운드·실기기·실제 아동 사용성·'재미'는 해당 방식으로 검증되기 전 **미검증**. 원본 상용 게임의 음악·애니메이션·그림/실루엣 모방 금지.

## 제작 우선 아트 방향 (제작 방식·팔레트는 실험 단계)

현재 구현된 SF Alpha의 짙은 남색 배경/민트·라일락 계열은 **임시 프로토타입 표현**이다. 이를 자동으로 최종 팔레트로 고정하지 않는다. 사용자 승인 방향은 **바닐라웨어 계열의 풍부한 회화적 2D 무대 표현 + 귀엽고 개성 있는 2D 외계 동료**다. 이것을 원본 IP 모사 없이 구현하며 **고해상도 2D 스프라이트 vs 저해상도 픽셀 아트 vs 일관된 혼합**을 실제 플레이 화면에서 2~3안 비교한 뒤 하나로 수렴한다.

1. **가독성 우선:** 세로 화면 360×640 기준 손가락 접근 가능한 큰 인터랙션, 공격 경고·보상·비동료 적의 구분.
2. **화면별 역할:** 우주 지도(광활함·세력 색) / 행성 탐험(발견·동선) / 우주선 내부(승무원 동선·시설) / 함선 전투(전술 피드백).
3. **원본 제작:** UI 정보 계층, 외계 생물의 큰 눈·재질·움직임, 정부·종교·해적 함선의 서로 다른 실루엣 등을 **자체 세계관 규칙**으로 만들되, 승인 전까지 가칭.
4. **게임플레이 우선:** 포스터·키아트가 아니라 플레이 화면 안에서 캐릭터·타격·동료·장비의 위치와 움직임을 볼 수 있는 파일을 우선.
5. **기술 제약 문서화:** 에셋마다 예상 크기/렌더링 방식(nearest/linear 등)/레이어/배경 투명 여부/프레임·방향·피벗/애니메이션 속도/출처와 라이선스 명시. 임의로 기존 128px Jiho 캐릭터 설정을 재사용하지 않음.

## 디자인 작업 카드 정의

| 항목 | 입력/출력 |
|---|---|
| 입력 | 최신 main SHA, 현재 플레이 가능한 화면의 캡처/소스, 관련 기능 1개, 사용자의 최신 피드백, 라우터 1~2개 |
| 산출물 | **한 장면**의 원본 디자인 또는 한 에셋 시트 + 파일 + 사용 의도 + 게임 화면에서의 크기/배치 |
| 검증 | 모바일 360×640 및 393×852 가독성; 플레이어·적·픽업 구분; 픽셀 스케일·경계 일관성 |
| 산출물 위치 | `assets/design-proposals/<feature>/` 또는 `docs/design/<feature>.md`, 브랜치 `design/<feature>` |
| 통합 규칙 | 디자인 PR → 개발자가 적용 시 픽셀 스케일/터치/성능/씬 테스트 → 게임 화면 검증 후 main 병합 |
| 상태 | `PROPOSED` / `REVIEWED` / `INTEGRATED` / `PLAYTESTED`; PR 제출을 곧 게임 반영으로 간주하지 않음 |

## 운영 권장

초기에는 **개발 매시간 :55 유지**, 디자인은 **매 3시간 정도** 독립 실행(예: 3시간 간격, 개발보다 앞서 에셋 제안 및 PR 공유)이 적절하다. 사용자가 매시간 별도 디자인을 명시적으로 승인하면 빈도는 변경 가능하지만, 충돌 방지 규칙은 유지한다. 과일 게임 보존 브랜치 수정 금지. 첫 디자인 우선순위: **스타맵 UI/함선 실루엣**과 **행성 전투 타격·보상 가독성**의 한 화면씩 비교; 첫 90초 실제 사용성 데이터가 없으면 사용자 테스트가 필요한 상태로 유지한다.
